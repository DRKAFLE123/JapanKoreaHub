---

## 1. Core Engineering Principles

### 1.1 Strict TypeScript & Zero "Any" Policy
- **No `any` or loose casting**: Every variable, function parameter, API payload, and database query result must have an explicit or inferred TypeScript interface/type.
- **Shared Type Definitions**: Place re-usable domain types in `types/` or co-locate with data modules in `lib/`.
- **Strict Null Checks**: Always handle `null` and `undefined` safely using optional chaining (`?.`) and nullish coalescing (`??`).

### 1.2 Next.js 16 App Router Conventions
- **Server Components by Default**: All components in `app/` are React Server Components (RSC) unless interactivity is strictly required.
- **Explicit `'use client'` Directives**: Add `'use client';` only to components using hooks (`useState`, `useEffect`, `useRouter`, Framer Motion, or browser Web APIs like Speech Synthesis).
- **Prevent Hydration Mismatches**:
  - Never render client-only data (like `new Date().toLocaleTimeString()` or `localStorage` values) directly on the first SSR pass without a mounted guard:
  ```typescript
  const [mounted, setMounted] = useState(false);
  useEffect(() => setMounted(true), []);
  if (!mounted) return null; // or skeleton placeholder
  ```
- **SEO & Metadata**: Every page must export an explicit `metadata` object or `generateMetadata()` function with descriptive titles, OpenGraph tags, and canonical URLs.

### 1.3 React 19 Standards
- **Clean State Hooks**: Avoid unnecessary derived state in `useState`. Compute values directly in render when possible.
- **Asynchronous Actions**: Use React 19 `useTransition` or Server Actions for non-blocking server mutations.
- **Cleanup in Effects**: Always return a cleanup function from `useEffect` when attaching listeners, timers, or speech synthesis utterances.

## 2. Styling & UI Design System Rules (Tailwind CSS v4)

- **Use Design Tokens, Not Arbitrary Hex Values**:
  - For Japanese theme accents: Use `accent-jp` / `bg-accent-jp` / `var(--accent-jp)` (`#C62828`).
  - For Korean theme accents: Use `accent-kr` / `bg-accent-kr` / `var(--accent-kr)` (`#1565C0`).
  - For surfaces: Use `var(--surface)`, `var(--surface-2)`, `card`, and `card-elevated`.
- **Dark Mode Support**:
  - Every new component must support both Light and Dark modes using CSS variables or Tailwind's `dark:` variant.
  - Surface backgrounds: Light `var(--surface)` (`#ffffff`), Dark `var(--surface)` (`#0f172a`).
- **Typography Font Classes**:
  - English / Latin UI: `font-sans` (`Inter`)
  - Nepali (Devanagari): `font-ne` (`Noto Sans Devanagari`)
  - Japanese: `font-jp` (`Noto Sans JP`)
  - Korean: `font-kr` (`Noto Sans KR`)
- **Strict Mobile Optimization**:
  - Always design mobile-first (`min-width: 0`).
  - Mobile bottom tab bar (`.bottom-tab-bar`) is strictly hidden above 768px (`md:hidden`). Never break this rule or desktop users will see an awkward bottom bar.

## 3. Database & Prisma ORM Standards

- **Prisma Client Singleton**: Never instantiate `new PrismaClient()` inside route handlers. Always import the shared instance from `lib/db.ts`.
- **Safe Database Queries**:
  - Always use parameterized queries generated by Prisma to prevent SQL injection.
  - Wrap multi-step related mutations in `prisma.$transaction([...])` to guarantee ACID atomicity.
  - Use `.select` or `.include` deliberately to avoid fetching unnecessary large text/blob fields.
- **Indexing & Performance**:
  - Every foreign key must have an `@@index` in `prisma/schema.prisma`.
  - Composite unique constraints must be respected (e.g., `@@unique([userId, itemType, itemId])`).

## 4. AI Assistant Operational Constraints

1. **NO Placeholder Code or Stubs**:
   - Never write `// TODO: implement later` or dummy mock data when actual schemas or datasets exist in `lib/` or `prisma/schema.prisma`.
   - Complete every function, validation logic, and return block in full.
2. **Preserve Documentation & Comments**:
   - Do not delete existing comments, translations, or docstrings unless they are provably obsolete or inaccurate.
3. **Robust Error Handling**:
   - All API route handlers must be wrapped in `try/catch` blocks.
   - Return structured JSON errors: `return NextResponse.json({ success: false, error: "Meaningful message" }, { status: 400 });`.
4. **Offline Gracefulness**:
   - When introducing client-side storage features, ensure Dexie.js catches quota errors or private browsing restrictions without crashing the page.
5. **No Breaking Path Modifications**:
   - Do not move or rename existing core directories (`/app`, `/components`, `/lib`, `/prisma`) without explicit user sign-off.

---

## 5. Security & Content Protection Rules

- **Protect Proprietary Curricula**:
  - Add `.content-watermark` to copyrighted textbooks, mock exam question pages, and diagrams.
  - Maintain the default `-webkit-user-select: none` on learning materials to deter unauthorized mass scraping, while ensuring `<input>`, `<textarea>`, and `[contenteditable]` retain full text selection capabilities.
- **Authentication Checks**:
  - Any mutating API route (creating posts, bookmarks, submitting exams, saving reviews) must verify user authentication via session tokens.

## 6. Pre-Commit / Pre-Deployment Checklist

Before committing or completing any task, ensure:
- [ ] Code compiles without TypeScript errors (`npx tsc --noEmit`).
- [ ] Next.js production build succeeds (`npm run build`).
- [ ] Responsive layout verified at 375px (iPhone SE), 768px (iPad), and 1440px (Desktop).
- [ ] Multilingual scripts render accurately with correct fonts applied.
- [ ] All environment variables are referenced via `process.env.*` with fallbacks where appropriate.

## 7. Universal RULES Template for Upcoming Projects

When initializing a new sister project, adapt this configuration:
1. Define primary architectural style (Next.js App Router vs Vite SPA).
2. Set strict TypeScript compiler options (`noImplicitAny: true`, `strictNullChecks: true`).
3. Codify the visual design tokens (color variables, typography, dark mode behavior).
4. Establish the AI non-negotiables: No stubs, full implementation, proper error responses.
